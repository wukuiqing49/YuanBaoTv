# Figma 转 Android 规则

## 阶段门禁

- 默认分为 `figma-process -> 用户确认 -> figma-code` 两阶段。
- 分析阶段只生成任务卡、资源清单和文件映射，不修改 Android 代码。
- 没有结构化图层、本地截图、Node 资源索引、规范化报告和页面任务卡时，不进入代码生成。
- 当前对象不是单个 Frame，或导航/Tab 页面没有拆分方案时，停在分析阶段。

## 映射与资源

- 页面按图层生成 Android 布局、item 和资源，禁止用整页截图或切片代替 UI。
- 图层映射具体到 Android 文件、XML id、dimen、drawable 和 string。
- 资源通过 Node ID 绑定；相似文件名不能作为唯一映射依据。
- 原始资源缺失时报告阻塞或记录用户确认的降级，禁止静默替换。
- Figma 状态栏、手势条、三键导航预览默认不绘制为业务 UI。

## 屏幕适配

- 使用“宽度建基准、高度填充屏幕”模型。
- Figma 逻辑宽度用于换算固定视觉尺寸；Frame 高度只用于区域比例和首屏可见量参考。
- Android 根布局填满真实屏幕，主内容区使用约束或滚动容器填充剩余高度。
- 任务卡必须包含关键尺寸合同、视觉高度拆分和 Insets owner 合同。
- 触控热区通过容器、padding 或 hitRect 扩大，不静默放大视觉元素。
- BottomNav 业务视觉高度与系统安全区分离。

## 实现与验收

- 优先复用项目 Base、Adapter、组件、样式和资源模块。
- 用户文案进入 strings；新增依赖联动架构和构建能力。
- 实现阶段逐项消费已确认任务卡，不在旧 UI 上局部修补后声称重建。
- 完成后运行 Figma、UI、i18n 和受影响模块编译验证；条件允许时进行设备截图对比。
