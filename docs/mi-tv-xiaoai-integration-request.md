# 小米电视系统小爱第三方播控接入咨询稿

状态：仅供审阅，尚未发送。2026-10-25。

## 可直接使用的咨询内容

希望确认小米电视内置小爱对第三方本地视频播放器的播控接入方式。

应用 YuanBaoTv，包名 `com.wkq.bao`，用于播放用户 NAS/本地媒体。测试设备 MiTV-MTEQ0，Android API 29，内置小爱 `com.xiaomi.voicecontrol` 5.12.0.7（5120007）。播放入口为 `com.wkq.bao.feature.app.mitv.MiTvPlayerActivity`。

应用已有 Media3 MediaSessionService，播放时系统可见活动媒体会话，具名标准控制器的播放/暂停曾验证通过。应用也能收到 `com.xiaomi.mitv.player.control` 的 `operate=pause/resume, cause=voicecontrol`，正确临时暂停并恢复。

但是在视频稳定播放期间，对电视内置小爱说“暂停”或“继续播放”，仍反馈“当前没有可操作的资源”。应用未收到对应用户播控指令。新播放入口生效后再次测试，结果相同。

请帮助确认：

1. 本型号及小爱版本是否支持普通第三方视频应用通过 Android MediaSession 获得语义播控？如支持，需要哪些声明、元数据和注册步骤？
2. 若必须经应用代理接入，应向哪个团队申请包名注册，是否有 SDK、接口文档及适配测试流程？是否允许个人开发者和 NAS/本地播放器申请？
3. 包名、播放入口或签名是否需要登记；有哪些版本、设备或分发渠道限制？
4. 暂停、继续、快进/后退、指定进度、下一集、倍速分别使用什么协议？如何区分用户指令和语音唤醒临时打断？
5. 是否有官方调试工具或可用于确认语义分发失败原因的日志开关？

可提供脱敏媒体会话状态、控制事件时间线和测试 APK。不会提供 NAS 账号密码、私有媒体地址或签名私钥。

## 渠道与证据边界

- [电视应用开发指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1329) 提供电视应用商店前置沟通渠道，可以咨询技术对接负责人；它没有承诺上架即获得小爱播控，也没有公开本问题对应的注册接口。
- [小爱语音服务平台](https://developers.xiaoai.mi.com/voiceservice/index) 的设备语音接入与“现有电视内置小爱控制第三方播放器”是不同需求，不能直接将设备 SDK 当成本问题解决方案。
- 本机静态检查发现的 `IAivse` 方法主要涉及唤醒、音频上传、识别跟踪；`IAivseConn.execCommand/registerCallback` 的存在本身不证明它允许第三方注册播放器。没有确认可用播控协议前不引入该私有接口。
- 本机应用代理表未包含本应用，结合真实失败日志，支持“当前分发路径未接通”的判断。该判断只适用于已检查的设备和版本。

## 接入后验收

每次测试先确认实际安装版本、前台播放入口、媒体已稳定播放和活动会话。保持测试窗口内不安装、不发送遥控/注入命令。

| 用户操作 | 必须观察的结果 |
| --- | --- |
| 说“暂停” | 语音结束后保持暂停，收到用户控制事件，不能仅短暂暂停后自动恢复 |
| 说“继续播放” | 恢复同一媒体，位置连续 |
| 快进/后退 | 时间位置按指令变化且不越界 |
| 下一集 | 切换正确集数，并遵循现有缺集确认逻辑 |
| 唤醒后询问天气 | 原本播放则恢复，原本暂停则仍暂停 |
| 退出播放器后发指令 | 不复活旧媒体，不误操作已经退出的会话 |

广播注入和标准控制器测试只验证应用接收端，不能替代上表的真实语音验收。
